# Native task integration boundary, resource policy updated 2026-10-12

The active path is now deterministic model preflight, frozen own-model native
replay, source-fact/history audit, physical field extraction and deterministic
delivery scoring. Neither source nor delivery assessment calls a model service.
No evaluator API key or model-selection environment variable is required.
model_definition.md and delivery_schema.md contain the current public checks;
earlier source-review protocols and decisions in scripts/evidence are historical.

## Implemented path

Setup verifies original source hashes and the installed Kratos 10.4.3 runtime,
then stages native tools, including native_model_contract.py. No private
generator, witness mesh, response curve or optimum is staged.

source_review.py freezes only source/native inputs, checks original provenance
and calls the deterministic model contract. A violated public check records
its reason and returns task zero before replay. Successful preflight produces
native-review.json bound to all three input hashes and the physical monitor
registration. This receipt checks geometry and declared model admissibility;
it is not physical certification or proof of replay time or memory compliance.

native_task.py stages evaluator-owned scripts and frozen inputs to a separate
guest directory. Native replay computes the common Stage7 prefix once and then
runs all five independent suffixes in parallel, including pos0, with source-fact,
role-section and construction-state audits. Saved delivered results and raw
tables are compared against the evaluator's physical observations. The numerical
0.5 and delivery 0.5 weights are unchanged;
presentation scoring now uses the disclosed PNG/structured-memo criteria.

The reader incorporates the validated shell/crown revision2 endpoint-coupling
exception and horizontal native hex Q4 interpolation. Both shell/crown boundary
traces remain observable and contribute to the maximum. Report comparison
accepts either complete boundary vector, without mixing their components.

## Published resource policy, 2026-10-12

The task VM is c4-standard-8 (8 vCPU, 30 GiB RAM). The original solver window
remains 18000 seconds (5 hours). The normal evaluation limit remains 7100 seconds
within the lifecycle's 7200; native replay has an exact 6600-second (110-minute)
wall-clock budget from native replay start. That budget includes the common
Stage7 prefix computed once, all five parallel suffixes, native state audits
and extraction. Delivery scoring does not extend the native replay deadline.

Each single-threaded replay worker, including the common-prefix worker, has
one CPU and a 4 GiB memory cap. Five suffix workers plus a 4 GiB coordinator
allowance share a 24 GiB aggregate cap without swap. The task VM leaves CPU
and memory headroom outside this allocation. Reduced guest affinity, inherited
quotas or insufficient memory must not silently reduce the scored allocation.
If the published allocation cannot be provided, evaluation is unavailable.

Exceeding the published replay time budget or a confirmed worker memory cap
receives zero with a resource-exhaustion receipt identifying the exhausted
resource and its limit evidence. Unexpected infrastructure or code faults and
incomplete replay without an established published resource violation remain
evaluator-unavailable, not zero. Reduced-resource or shortened diagnostic
replays cannot justify zero for resource exhaustion.

There is no element-count cap. Model authors may choose or revise the mesh
within the existing local-refinement and accuracy requirements. The resource
limit does not relax those checks or the physics, material, construction-stage,
solver tolerance or native audit requirements. Recommend testing native replay
within these limits using the supplied tools and allowing adequate time and memory headroom;
no additional mesh/domain study is mandatory. Public preflight does not certify
resource compliance. This policy publication records no new runtime validation.
