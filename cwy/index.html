Chapter 01

题目原文与完整中文翻译

下面英文内容是任务对 Agent 展示的原始题面。这里不改写、不总结。路径使用任务卡中的公开形式 default/input 和 default/output。

Original task promptVerbatim
You are tasked with writing gen.cpp, a C++ program that prints one complete valid test case to stdout per invocation and accepts a single integer seed as argv[1] (e.g. ./gen 1, ./gen 2, ./gen 50) to vary output across invocations.

The problem statement is provided in Binary String Copying Problem Statement.pdf. The 10 submission IDs are listed in Binary String Copying Inputs.xlsx: they are each a single letter, proceeding alphabetically from top to bottom (row 2 is a, row 3 is b, etc). Without knowledge of the submission implementations, the generator must be designed by reasoning purely from the problem structure about what kinds of inputs stress different algorithmic approaches:

To trigger TLE on slow solutions, generate worst-case inputs where the sums of n and m hit their limits (sum of n = sum of m = 200000) using a single large test case with m operations whose [l, r] ranges cover wide spans of a string with many alternating 0/1 segments, forcing per-query string reconstruction or hashing of long substrings.

To trigger WA on incorrect solutions, generate inputs that exercise boundary conditions: operations with l = r (a no-op sort that produces the original string and must be deduplicated against any other no-op operation), strings that are already sorted everywhere except at narrow boundary windows so distinct (l, r) pairs collapse to the same sorted result, all-0 and all-1 strings where every operation is a no-op, and ranges whose sorted result equals the original because the substring is already sorted — all cases where naive comparison or careless hashing diverges from the correct deduplicated count.

To produce both AC and WA verdicts from the same submission across 50 seeds, the 50 generated test cases must include a mix of small inputs (n, m <= 100) and maximum-size inputs so that a randomized or hash-based solution coincidentally agrees on small inputs but collides on large adversarial ones.

gen.cpp must be compiled and verified locally with g++ before submission.

## Input Files
Located at: `default/input`
- `Binary String Copying Problem Statement.pdf` — full problem statement
- `Binary String Copying Inputs.xlsx` — submission IDs

## Output
Save your final generator as: `default/output/gen.cpp`

## Compilation
Use: `g++ -O2 -std=c++17 gen.cpp -o gen`

## Constraints
- Each test case must be valid input for the Binary String Copying problem
- Sum of n across all test cases in one invocation must not exceed 200000
- Sum of m across all test cases in one invocation must not exceed 200000
- Each query must satisfy 1 <= l <= r <= n

## Evaluation
Your generator will be called as `./gen $seed` for seeds 1 through 50 to produce 50 test cases. Submission j serves as the reference solution. Each of the remaining 9 submissions will be run against all 50 test cases with a 2-second time limit and 256MB memory limit per execution. The verdict for each submission is the union of all outcomes (AC, TLE, WA, RE) across the 50 test cases, joined by "/" in the order AC/TLE/WA/RE.

完整中文翻译

你的任务是编写 gen.cpp。它是一个 C++ 程序，每次运行时向标准输出打印一份完整且合法的测试用例，并通过 argv[1] 接收一个整数 seed，例如 ./gen 1、./gen 2、./gen 50，从而让不同运行产生不同输出。

题目说明位于 Binary String Copying Problem Statement.pdf。10 个提交的编号列在 Binary String Copying Inputs.xlsx 中。每个编号都是一个字母，按照表格从上到下依次排列，第 2 行是 a，第 3 行是 b，以此类推。你无法看到这些提交的具体实现，因此只能从题目本身的结构出发，推理哪些输入会对不同算法形成压力，并据此设计生成器。

为了让低效程序触发 TLE，应生成最坏情况输入：让 n 的总和与 m 的总和都达到上限 200000。可以使用一个大型测试用例，其中包含 m 次操作，各个 [l,r] 区间覆盖具有大量 0/1 交替段的字符串中的较宽范围。这样可以迫使某些程序在每次查询时重新构造字符串，或对很长的子串进行哈希，从而超时。

为了让错误程序触发 WA，应生成覆盖边界情况的输入，包括：

  • l = r 的操作。这种排序不会改变原字符串，必须与其他不改变字符串的操作去重；
  • 字符串几乎已经排好序，只有狭窄边界窗口未排序。不同的 (l,r) 可能得到完全相同的排序结果；
  • 全 0 字符串与全 1 字符串。所有操作都不会改变字符串；
  • 被选择的子串本身已经有序，因此排序结果仍等于原字符串。

这些情况会使简单粗暴的比较方式或不谨慎的哈希实现，与正确的去重计数产生差异。

为了让同一个提交在 50 个 seed 的运行中同时产生 AC 和 WA，生成的 50 份测试数据必须混合小规模输入与最大规模输入。小规模输入要求 n,m <= 100。这样，随机化算法或依赖哈希的算法可能在小数据上偶然正确，却在大型对抗数据上发生碰撞或错误。

提交前，必须使用 g++ 在本地编译并验证 gen.cpp。

输入文件

文件位于 default/input：

  • Binary String Copying Problem Statement.pdf：完整题目说明；
  • Binary String Copying Inputs.xlsx：提交编号。

输出

将最终生成器保存为 default/output/gen.cpp。

编译

使用命令：g++ -O2 -std=c++17 gen.cpp -o gen。

约束

  • 每次生成的测试必须是 Binary String Copying 问题的合法输入；
  • 一次运行输出的所有测试中，n 的总和不能超过 200000；
  • 一次运行输出的所有测试中，m 的总和不能超过 200000；
  • 每次查询都必须满足 1 <= l <= r <= n。

评测方式

评测器会使用 seed 1 到 50 调用生成器，即执行 ./gen $seed，从而得到 50 份测试数据。提交 j 作为参考正确程序。其余 9 个提交会在全部 50 份测试上运行，每次执行的时间限制为 2 秒，内存限制为 256 MB。每个提交的最终 verdict 是它在 50 份测试中出现过的全部结果的并集，可能包括 AC、TLE、WA、RE，并按照 AC/TLE/WA/RE 的顺序使用斜杠连接。

Chapter 02

如果你是人，这道题应该怎么解

先分清两层题目：内层是 Binary String Copying 算法题；外层才是 ALE 任务。你不提交内层题目的解法，而是提交一个能生成内层题目测试数据的程序。

2.1 先理解内层算法题

对二进制字符串的区间 [l,r] 排序，等价于把区间内的 0 全部移到前面、1 全部移到后面。判断两次操作是否产生同一结果时，关键不是原始的 l,r，而是：

  1. 区间内第一个 1 的位置，记作 L；
  2. 区间内最后一个 0 的位置，记作 R；
  3. 如果 L > R，区间本来已经有序，排序不会改变字符串；
  4. 否则，真正发生变化的核心范围由 (L,R) 决定。多个不同的 [l,r] 可能归一化到同一个 (L,R)。

2.2 再猜隐藏错误程序会错在哪里

可能的错误实现对应攻击数据预期结果
直接把不同的 [l,r] 当成不同答案设计大量不同区间，但它们归一化到相同 (L,R)WA
没有合并所有“不改变原串”的查询全 0、全 1、单点区间、已经有序的子串WA
第一个 1 或最后一个 0 的边界处理错误变化只发生在开头、结尾或很窄的边界窗口WA
每次查询复制、排序或哈希长子串sum(n)=sum(m)=200000，大量宽区间TLE
随机化或哈希实现不稳定部分 seed 使用温和小数据，部分 seed 使用大型对抗结构AC/WA

3.3 十类大型字符串

  1. 完全交替的 010101...；
  2. 长短不一的连续 0/1 段；
  3. 全 0；
  4. 全 1；
  5. 000...111... 的正向有序串；
  6. 111...000... 的反向结构；
  7. 以 0 为主，夹杂少量孤立或块状的 1；

Chapter 05

这道任务真正测什么，哪里可能不够好

它想测的能力

  • 阅读并理解算法规格；
  • 推导正确程序的关键不变量；
  • 预测常见错误实现与复杂度问题；
  • 设计边界、极限、等价类和对抗测试；
  • 把测试策略写成可重复执行的生成器；
  • 自行编译和检查产物。

因此，它模拟的是人类竞赛出题人、Hack 数据设计者或软件测试工程师，而不是普通参赛者。

verifier 的优点

  • 直接编译、执行隐藏程序，不依赖 LLM judge；
  • AC、WA、TLE、RE 都是可复现的程序行为；
  • 正确程序 j 是硬门控，可以阻止非法或误伤正确解的数据拿分；
  • 包含不同错误实现，也包含要求 AC/WA 混合结果的不稳定实现。

需要警惕的局限

  • 固定隐藏程序依赖：高分只说明抓住了这 10 个实现，不代表覆盖所有潜在 bug；
  • 题面提示较多：原题已经明确告诉 Agent 应构造哪些边界与极限数据，降低了自主发现测试策略的难度；
  • 可能过拟合：一旦知道隐藏程序类型，生成器可以专门攻击这些程序，而不具备一般化测试能力；
  • 分数解释有限：0.9 与 1.0 表示匹配固定 verdict 目标，不直接等价于真实软件测试覆盖率；
  • 数据分发成本高：单题 reference 很小，但官方本地 Docker 数据被打入约 44.4 GB 的单一归档，增加复现成本。
如果你要设计新题：保留“隐藏正确解 + 多类错误解 + 投机解 + 确定性 verifier”的结构，同时减少题面对攻击方法的直接提示，并使用更多独立错误实现检验泛化能力。
