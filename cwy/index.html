1.3 ALE 任务说明完整中文翻译

你的任务是编写 gen.cpp。它是一个 C++ 程序，每次运行时向标准输出打印一份完整且合法的测试用例，并通过 argv[1] 接收一个整数 seed，例如 ./gen 1、./gen 2、./gen 50，从而让不同运行产生不同输出。

题目说明位于 Binary String Copying Problem Statement.pdf。10 个提交的编号列在 Binary String Copying Inputs.xlsx 中。每个编号都是一个字母，按照表格从上到下依次排列，第 2 行是 a，第 3 行是 b，以此类推。你无法看到这些提交的具体实现，因此只能从题目本身的结构出发，推理哪些输入会对不同算法形成压力，并据此设计生成器。

为了让低效程序触发 TLE，应生成最坏情况输入：让 n 的总和与 m 的总和都达到上限 200000。可以使用一个大型测试用例，其中包含 m 次操作，各个 [l,r] 区间覆盖具有大量 0/1 交替段的字符串中的较宽范围。这样可以迫使某些程序在每次查询时重新构造字符串，或对很长的子串进行哈希，从而超时。

为了让错误程序触发 WA，应生成覆盖边界情况的输入，包括：

  • l = r 的操作。这种排序不会改变原字符串，必须与其他不改变字符串的操作去重；
  • 字符串几乎已经排好序，只有狭窄边界窗口未排序。不同的 (l,r) 可能得到完全相同的排序结果；
  • 全 0 字符串与全 1 字符串。所有操作都不会改变字符串；
  • 被选择的子串本身已经有序，因此排序结果仍等于原字符串。

这些情况会使简单粗暴的比较方式或不谨慎的哈希实现，与正确的去重计数产生差异。

为了让同一个提交在 50 个 seed 的运行中同时产生 AC 和 WA，生成的 50 份测试数据必须混合小规模输入与最大规模输入。小规模输入要求 n,m <= 100。这样，随机化算法或依赖哈希的算法可能在小数据上偶然正确，却在大型对抗数据上发生碰撞或错误。

提交前，必须使用 g++ 在本地编译并验证 gen.cpp。

  • Binary String Copying Inputs.xlsx：提交编号。

编译

约束

  • 每次生成的测试必须是 Binary String Copying 问题的合法输入；
  • 一次运行输出的所有测试中，n 的总和不能超过 200000；
  • 一次运行输出的所有测试中，m 的总和不能超过 200000；
  • 每次查询都必须满足 1 <= l <= r <= n。

C. Binary String CopyingProblem statement
time limit per test: 2 seconds
memory limit per test: 256 megabytes

You are given a string s consisting of n characters 0 and/or 1.

You make m copies of this string, let the i-th copy be the string t_i. Then you perform exactly one operation on each of the copies: for the i-th copy, you sort its substring [l_i; r_i] (the substring from the l_i-th character to the r_i-th character, both endpoints inclusive). Note that each operation affects only one copy, and each copy is affected by only one operation.

Your task is to calculate the number of different strings among t_1, t_2, ..., t_m. Note that the initial string s should be counted only if at least one of the copies stays the same after the operation.

Input
The first line contains a single integer t (1 <= t <= 10^4) — the number of test cases.

The first line of each test case contains two integers n and m (1 <= n, m <= 2 * 10^5) — the length of s and the number of copies, respectively.

The second line contains n characters 0 and/or 1 — the string s.

Then m lines follow. The i-th of them contains two integers l_i and r_i (1 <= l_i <= r_i <= n) — the description of the operation applied to the i-th copy.

The sum of n over all test cases does not exceed 2 * 10^5. The sum of m over all test cases does not exceed 2 * 10^5.

Output
Print one integer — the number of different strings among t_1, t_2, ..., t_m.

1.5 PDF 算法题完整中文翻译

C. 二进制字符串复制

单个测试的时间限制为 2 秒，内存限制为 256 MB。

给定一个长度为 n、只包含字符 0 和 1 的字符串 s。

将这个字符串复制 m 份，第 i 份记为 t_i。对每一份副本恰好执行一次操作：在第 i 份副本中，把从第 l_i 个字符到第 r_i 个字符的子串按升序排序，两个端点都包含在内。每次操作只影响一份副本，每份副本也只执行一次操作。

任务是计算 t_1、t_2、...、t_m 中有多少个不同的完整字符串。只有当至少一份副本执行操作后仍与原字符串相同时，原字符串 s 才会被计入。

Input（输入）

  • 第一行是整数 t，满足 1 <= t <= 10^4，表示测试组数。
  • 每组测试的第一行包含 n 和 m，均满足 1 <= n,m <= 2*10^5。n 是字符串长度，m 是副本数，也等于查询数。
  • 第二行是长度为 n 的二进制字符串 s。
  • 随后有 m 行。第 i 行给出 l_i r_i，满足 1 <= l_i <= r_i <= n，表示第 i 份副本需要排序的区间。
  • 所有测试组的 n 总和不超过 200000，m 总和也不超过 200000。

Output（输出）

对每组测试输出一个整数，表示执行各自操作后，m 份副本中不同完整字符串的数量。

样例解释

第一组的五份副本分别得到 011100、011100、101100、101100、000111，去重后有三个字符串，因此输出 3。第二组得到 100111、001111、001111、010111，去重后也有三个字符串，因此输出 3。第三组只有一个长度为 1 的字符串，排序后不变，因此输出 1。

假设原字符串是 0101，有四条查询。官方先复制四份完全相同的 0101，然后每份只执行自己对应的一条查询。

2.5 正确程序怎样判断两条查询是否产生同一个字符串

对查询 [l,r]，真正会发生位置交换的区域，从区间里的第一个 1 开始，到区间里的最后一个 0 结束：

  1. 从 l 向右找第一个 1，记为 x；
  2. 从 r 向左找最后一个 0，记为 y；
  3. 如果找不到，或者 x > y，区间本来已经有序，结果仍是原字符串；
  4. 否则，排序结果可以用有效边界对 (x,y) 表示。

例如在 0101 中，查询 [2,3] 和 [1,4] 的表面区间不同，但它们真正需要调整的部分都是从第 2 位的 1 到第 3 位的 0，因此得到同一个结果 0011。大量错误程序会在这里发生重复计数、哈希碰撞或边界错误。

3.2 它采用的完整解题路线

  1. 确认输出形式：最终只需创建一个能编译的 gen.cpp，每次根据 seed 打印完整输入。
  2. 理解正确答案结构：查询结果由区间内第一个 1 和最后一个 0 形成的有效边界决定。
  3. 覆盖小型边界：对多个短字符串枚举全部区间，保证单点、空变化、相同结果和边界位置都会出现。
  4. 构造最大规模测试：把剩余的 n、m 预算全部交给第 10 个测试，给慢算法和哈希算法足够压力。
  5. 让 50 个 seed 有差异：轮换十类长字符串，每类在 50 个 seed 中出现五次，同时改变内部参数和查询顺序。
  6. 混合查询策略：加入整段、单点、连续字符段、同一有效边界的多种外扩区间、宽区间和随机区间。
  7. 本地检查：编译，运行 1–50 的 seed，验证格式、边界与总规模。

makeLargeString()按照 seed 轮换 10 类字符串结构覆盖交替串、全零、全一、有序、逆序、周期和随机结构
collectAnchors()寻找第一个 1 与最后一个 0 的有效边界批量构造不同 [l,r] 对应同一实际变化范围的查询
makeLargeQueries()混合整段、单点、连续段、宽区间和随机区间同时攻击正确性和时间复杂度

3.5 关键代码一：seed 真正控制生成内容

gen.cpp · main()读取外层 seed
uint64_t seed = 1;
if (argc >= 2) {
    seed = strtoull(argv[1], nullptr, 10);
}
if (seed == 0) seed = 1;

TestGenerator generator(seed);
vector<TestCase> tests = generator.build();

因此 ./gen 1 与 ./gen 2 会产生不同内容；相同 seed 再次运行时仍得到相同结构，便于复现。

3.6 关键代码二：小字符串枚举所有查询

gen.cpp · addExhaustive()完整覆盖短串区间
for (int length = 1; length <= n; ++length) {
    for (int left = 1; left + length - 1 <= n; ++left) {
        test.queries.emplace_back(left, left + length - 1);
    }
}

长度为 n 的字符串共有 n(n+1)/2 个合法区间。全部枚举后，单字符、整段、已经有序、跨越 1/0 边界等情况都会进入测试。

3.7 关键代码三：围绕同一有效变化区域制造等价查询

gen.cpp · collectAnchors()定位有效边界
int first_one = one_starts[...];
int last_zero = zero_ends[...];
int left_low = previous_one[first_one] + 1;
int right_high = next_zero[last_zero] - 1;
anchors.push_back({left_low, first_one, last_zero, right_high});

对于同一个 first_one 和 last_zero，左端点可以在 left_low..first_one 中变化，右端点可以在 last_zero..right_high 中变化。这些查询写法不同，却可能产生同一个排序结果，正好检验程序有没有正确去重。

3.8 关键代码四：小测试用掉一部分预算，大测试填满剩余预算

gen.cpp · build()核心规模控制
const int large_n = 200000 - used_n;
const int large_m = 200000 - used_m;

TestCase large;
large.s = makeLargeString(large_n, static_cast<int>((seed - 1) % 10));
large.queries = makeLargeQueries(
    large.s, large_m, static_cast<int>((seed - 1) % 10)
);
tests.push_back(move(large));

这种写法保证每次调用都满足限制，同时把 sum(n) 和 sum(m) 精确推到 200000。慢程序需要面对接近题目上限的真实工作量。

3.9 十类大型字符串分别测试什么

  1. 完全交替：010101...，包含大量 1/0 逆序边界和宽区间变化。
  2. 长短不一的连续段：检验连续块边缘和跨块查询。
  3. 全 0：所有查询都不改变字符串，正确答案只能是 1。
  4. 全 1：同样检验所有操作都是 no-op 的去重。
  5. 正向有序：000...111...，大量区间本身已经有序。
  6. 反向结构：111...000...，宽区间排序会移动大量字符。
  7. 稀疏 1 块：检验孤立位置、很短有效变化区和很长无关前后缀。
  8. 确定性伪随机串：提供不规则边界，减少只适配规则字符串的风险。
  9. 周期串：制造大量相似局部结构，给哈希和去重增加压力。
  10. 不规则长段：组合多种长度的 0/1 run，检验边界扫描和长区间。

(seed - 1) % 10 决定使用哪一类。seed 1 到 50 会让十类结构各出现五次，同时每次内部参数不同。

4.2 “50 个 Case”到底指什么

这里同时存在三层数量，必须分开理解：

层次数量具体含义
外层生成运行50官方调用 ./gen 1 到 ./gen 50，得到 50 个文件
每个文件里的内部测试10本次 gen.cpp 每次都打印 t=10，因此每个文件含 10 组 Binary String Copying 测试
隐藏解题程序10a.cpp、b.cpp、...、j.cpp

所以，一个隐藏程序会被启动 50 次，每次读取一个含 10 组内部测试的文件。10 个隐藏程序共有 10*50=500 次正式判题进程；参考程序 j 还会额外运行 50 次生成标准答案。再加上生成器本身运行 50 次，完整脚本共启动 600 次主要程序进程。

4.3 judge.sh 从头到尾执行什么

编译编译 gen.cpp、参考 j 和 a–j 全部程序。
生成 50 份输入保存为 test_1.txt 到 test_50.txt。
生成标准答案j 读取每份输入，输出 ref_1.txt 到 ref_50.txt。
逐程序运行a–j 各自运行 50 份输入，每次限制 2 秒、256 MB。
聚合并算分记录 AC/WA/TLE/RE，再匹配 10 个得分点。
  1. g++ -O2 -std=c++17 -o gen_bin gen.cpp 编译生成器。
  2. 用同样参数编译 j.cpp，得到参考程序 reference。
  3. 循环 seed 1–50：./gen_bin $seed > tests/test_$seed.txt。
  4. 循环 seed 1–50：让 j 读取测试文件，把十行标准答案写入对应的 ref_$seed.txt。
  5. 对 a–j 中的每个程序，再循环 50 个 seed，并用 timeout 2 和 256 MB 虚拟内存限制启动它。
  6. 程序正常结束时，脚本把它的完整 stdout 与参考文件逐字比较。
  7. 50 次结束后，将该程序出现过的全部状态按照 AC/TLE/WA/RE 顺序合并。

4.4 单个 seed 怎样判定 AC、WA、TLE 或 RE

单次运行发生什么该 seed 的状态
进程在 2 秒内正常结束，10 行输出与 j 完全相同AC
进程正常结束，但任意一行数字不同、少行或多行WA
timeout 返回 124，说明超过 2 秒TLE
进程异常退出，返回其他非零状态RE

例如 seed 22 的输入包含 10 个内部测试。参考程序最后一行输出 106429，一次复跑中 a.cpp 最后一行输出 106428。前九行即使都相同，这个 seed 对 a 仍然记为 WA。

4.5 为什么最终会出现 AC/WA 这种组合

Verifier 不统计“通过了多少个 seed”，只记录某种状态有没有出现过：

  • 50 个 seed 全部正确：最终是 AC；
  • 49 个正确、1 个错误：最终是 AC/WA；
  • 有 AC、有 TLE、也有 WA：最终是 AC/TLE/WA；
  • 只要 j 的最终集合不严格等于 {AC}，整题直接得到 0 分。

4.9 这个 verifier 实际在测什么

它主要测 Agent 能否像竞赛 Hack 数据设计者或测试工程师一样，读懂规格、推导正确不变量、猜测常见错误、生成极端与等价类测试，并把策略实现成可重复执行的程序。AC、WA、TLE、RE 都来自真实编译执行，不需要 LLM judge。

分数也有明确边界：0.5 表示命中了固定隐藏程序中的 5 个得分点，不能直接解释为“覆盖了现实世界 50% 的程序错误”。
