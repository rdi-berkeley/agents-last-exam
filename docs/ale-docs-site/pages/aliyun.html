Alibaba Cloud ECS

Run every unit on a fresh ECS instance. The aliyun provider is the Alibaba Cloud counterpart of the Google Cloud and AWS paths — same per-snapshot model, same image-family names.

What the provider manages

The aliyun provider selects the image, instance type, GPU, and candidate zones from the task snapshot and environment profile. It runs an instance, waits for the in-guest CUA server, runs one unit, then deletes, stops, or keeps the instance according to cleanup_mode.

  • Ubuntu and Windows custom images are supported.
  • GPU snapshots use a gn7i (NVIDIA A10) instance and retry across configured zones when capacity is unavailable.
  • CPU tasks use the task-card instance type, with a C-family to G-family (ecs.c* → ecs.g*) fallback when applicable.
  • Windows snapshots apply the configured desktop resolution before the run starts.

Understand the credential model

CredentialPurpose
aliyun configure (RAM-user AccessKey)The host creates, describes, stops, and deletes ECS instances.
Instance RAM role (ram_role_name)Attached at launch; the in-box ossutil uses it for task-data reads and optional output uploads — no key is injected into the sandbox (the Alibaba analogue of AWS's IAM instance profile).

Unlike Google Cloud, there is no service-account key file to push into the sandbox: OSS access is granted by the instance RAM role, so the yaml never names a secret.

Before you begin

  • An Alibaba Cloud account, and a RAM user with an AccessKey pair (do not use the root account key).
  • The Alibaba Cloud CLI (aliyun) installed on the ALE host, plus ossutil for OSS transfers.
  • ECS and OSS activated in your target region.
  • Sufficient vCPU and GPU quota for your intended concurrency.

1. Authenticate

Create an AccessKey pair for a RAM user in the console (RAM → Users → <user> → Create AccessKey), then configure the CLI: 

export ALE_ALIYUN_REGION="cn-hangzhou"

aliyun configure set \
  --profile ale \
  --mode AK \
  --region "$ALE_ALIYUN_REGION" \
  --access-key-id  <AccessKeyId> \
  --access-key-secret <AccessKeySecret>

The provider uses the ambient credential chain, so you can equivalently export ALIBABA_CLOUD_ACCESS_KEY_ID / ALIBABA_CLOUD_ACCESS_KEY_SECRET.

2. Import the sandbox images

ALE publishes prebaked Ubuntu and Windows raw images on GCS. Import them into your account once as ECS custom images, tagged ale:image-family=<name> (the tag the provider resolves): 

./scripts/aliyun/import_images.sh all   # ale-ubuntu22, ale-win10, ale-win-server

The script streams each image from GCS through an OSS import bucket, calls aliyun ecs ImportImage, and bakes the aliyun CLI + ossutil into the Linux image (needed for oss:// task data / output).

3. Create the instance RAM role (for oss:// data/output)

Only needed when task_data_source or output_path points at oss://. Create a RAM role the ECS service can assume, grant it OSS access, and name it in each snapshot's ram_role_name: 

aliyun ram CreateRole --RoleName ale-sandbox \
  --AssumeRolePolicyDocument '{"Statement":[{"Action":"sts:AssumeRole","Effect":"Allow","Principal":{"Service":["ecs.aliyuncs.com"]}}],"Version":"1"}'
aliyun ram AttachPolicyToRole --PolicyType System \
  --PolicyName AliyunOSSReadOnlyAccess --RoleName ale-sandbox

4. Create a restricted security group

ALE connects directly to the CUA server on TCP port 5000. Restrict ingress to the public CIDR of the machine running ALE. Do not expose the control server to the entire internet. 

export ALE_CLIENT_CIDR="203.0.113.10/32"   # the ALE host's public IP/CIDR

VPC=$(aliyun ecs DescribeVpcs --RegionId "$ALE_ALIYUN_REGION" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["Vpcs"]["Vpc"][0]["VpcId"])')
SG=$(aliyun ecs CreateSecurityGroup --RegionId "$ALE_ALIYUN_REGION" \
  --SecurityGroupName ale-sandbox --VpcId "$VPC" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["SecurityGroupId"])')
aliyun ecs AuthorizeSecurityGroup --RegionId "$ALE_ALIYUN_REGION" \
  --SecurityGroupId "$SG" --IpProtocol tcp --PortRange 5000/5000 \
  --SourceCidrIp "$ALE_CLIENT_CIDR"

The provider resolves the security group by name to its id and VPC, then picks a vSwitch in each candidate zone within that VPC. Tag a vSwitch with project=ale to pin which one the provider prefers.

5. Create a results bucket

Optional when output_path: local; recommended for large batch artifacts. Create an OSS bucket and grant the instance RAM role write access, then set output_path: oss://<bucket>. 

ossutil mb "oss://ale-results-$(whoami)" --region "$ALE_ALIYUN_REGION"

6. Configure ALE

The shipped configs/environments/environment_aliyun.yaml maps all five task snapshots to Alibaba Cloud. Set the region and zones to match your account, start with selected_tasks/helloworld.txt, then use selected_tasks/unlicensed.txt for the public unlicensed set.

Capacity and cleanup

GPU capacity is volatile, so the shipped profile lists several fallback zones. Your account still needs quota in the selected region. Set concurrency below your vCPU, GPU, public-IP, and LLM limits.

Use cleanup_mode: delete for batch runs. If the host process is terminated before cleanup completes, inspect leftovers by tag: 

aliyun ecs DescribeInstances --RegionId "$ALE_ALIYUN_REGION" \
  --Tag.1.Key purpose --Tag.1.Value ale-run
