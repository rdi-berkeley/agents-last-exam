# ALE v1.1

ALE v1.1 is a coordinated task-code, data and environment update. Use the
versioned configurations in this checkout together. Do not combine v1.1 task
code with older unversioned VM images or an old `task-data` directory.

The **2026-10-08 rerelease selects 151 tasks**. Six formerly licensed tasks now
use open-source Linux workflows with similar business logic and deliverable
goals. They retain their task IDs; this does not claim identical results from
the former proprietary applications. The [task inventory](v1.1-tasks.md) lists
the conversions and the earlier repair/audit scope.

`engineering/mold-flow` is removed from the selected release, published task
registration and runnable task packages because the complete four-cavity
fill/pack/cool/demold workflow has not been validated with open-source software
at the original scope. No reduced simulation task replaces it.

The full and unlicensed lists each contain 151 tasks, the CPU allowlist 146,
the Linux list (`ale_cli.txt`) 111, and the supported Docker allowlist 102. The CLI list
means all selected `cpu-free-ubuntu` tasks, including desktop workflows; it is
not a claim that these tasks require only terminal interaction. Existing
difficulty assignments and unrelated track exclusions are retained.

Matching task metadata, inputs, references, the complete data archive and QEMU
images are published on Hugging Face `main` and `v1.1`. Use the immutable
revisions and image/runtime identities in the release manifest and profiles.

## What changes

- Instructions, task cards and graders share explicit contracts: simulation
  interfaces, estimator settings, grading rubrics and output conventions.
- Corrected references and packaging ship with matching code. Examples include
  genomic intervals, robotics observation descriptions, scientific calculations
  and the SUMO evaluator archive.
- Graders inspect deliverables, accept valid equivalent syntax, and distinguish
  a legitimate zero from evaluator failure. Follow-ups repair Amber flag/path/
  mask/radii parsing, rounding and report wording without relaxing scientific
  acceptance thresholds.
- Versioned QEMU/GCloud disks contain the task data. Docker contains matching
  Linux userspace without task data and uses a separately pinned archive.
  Both distributions include the final IDP executable compatibility update.
- Provider/staging fixes preserve large artifacts, symlinks and reference
  isolation. Docker prompts disclose configured CPU/memory ceilings.
- Required harness/lifecycle fixes and upstream Antigravity support are included.
  Shared usage JSON field names and historical run records do not change.

## QEMU and GCloud

The new Linux image includes the six converted runtimes and the matching
111-task Linux data projection. Windows retains its existing QCOW2 bytes and
GCloud image IDs: its 40-task data projection is unchanged and verified against
the current release. Its older embedded global release marker is qualified by
the public [platform projection record](https://huggingface.co/datasets/agents-last-exam/ale-images-qcow2/blob/v1.1/v1.1-oss-platform-projections.json).

Use `configs/environments/qemu.yaml`, retaining its immutable `hf_revision`,
with `selected_tasks/cpu_unlicensed.txt`. Budget for both disks at their pinned
sizes, plus download headroom, overlays, output and retained guests. Never use
host `/tmp` or `/dev/shm` for these files. Omit `hf_revision` when switching a
disk source to GCS or a local file.

For GCloud, follow the [quickstart](../quickstart.md), copying the versioned
images into your project. The provider resolves names in that project:

```bash
jq -r '.images[] | .gcloud | [.name, .project] | @tsv' releases/v1.1/assets.json |
while IFS=$'\t' read -r image source_project; do
  gcloud compute images create "$image" \
    --source-image="$image" --source-image-project="$source_project"
done
```

Use `configs/environments/environment_gcloud.yaml` with
`selected_tasks/unlicensed.txt`. Windows GPU tasks use the versioned public
Windows image plus the accelerator configuration. The selected release no
longer contains tasks requiring licensed application activation.

Start with `selected_tasks/hello_both.txt` and `--dry-run` before a batch.
The September validation used Kimi Code/K3 max; the October six-task review
used Codex. Both set `wall_time_s: 18000`.
Set that explicitly for a five-hour benchmark run; the generic example has a
different timeout. Agent credentials remain in your `secret/.env`.

## Docker

The shipped Docker profile pins the published v1.1 runtime by registry digest.
To pull it explicitly:

```bash
IMAGE=$(jq -r '.docker.pinned_image' releases/v1.1/assets.json)
docker pull "$IMAGE"
```

Authenticate the HF CLI with approved archive access, then:

```bash
REVISION=$(jq -r '.huggingface.archive.revision' releases/v1.1/assets.json)
SHA256=$(jq -r '.task_data.archive_sha256' releases/v1.1/assets.json)
scripts/fetch_task_data.sh --revision "$REVISION" --sha256 "$SHA256"
```

The script verifies both pins, preserves native modes/symlinks, and installs
into an absent or empty `task-data-v1.1`. It never merges into stale task data
or silently falls back to main. Budget for the pinned archive and its extracted
tree, in addition to the runtime and per-run working directories.

Use `configs/environments/docker.yaml` and `selected_tasks/docker_support.txt`
(102 supported Linux tasks). The three added Blender building, MuseScore
transcription and Ardour migration workflows pass native output checks in the
published container. These checks establish runtime operation and output
creation; they are not fresh agent evaluations. The paired VM/Docker reviews
cover the historical 99-task subset, not a new full 102-task run.

G-code, Road and inner-support are excluded from the default rootless Docker
profile. G-code requires nested PID/network namespaces; Road and inner-support
require systemd supervision, and inner-support also requires writable delegated
cgroups. Use QEMU for these tasks to preserve their isolation and resource
limits.

ALE stages the current task's input/software before the
solver and references only after it finishes. Never mount the complete host
dataset into an agent container. Provider profiles default to
`output_path: null`. Keep this setting for benchmark experiments and inspect
deliverables in retained sandboxes; metadata, trajectories, evaluations and
telemetry are still collected.

## Other data consumers

HF inputs/references retain `tasks/<domain>/<task>/<variant>` layout. Small
lossless transport archives carry filenames the Hub rejects and four native
runtime symlinks. Follow each dataset card's restore instructions. The complete
Docker archive already has native layout and needs no additional extraction.

Direct `task_data_source: hf://...` staging remains unimplemented. For Docker,
download the archive with `fetch_task_data.sh` and use `local:task-data-v1.1`;
QEMU/GCloud use baked data or guest-side GCS staging.

For guest-side GCS staging, use `task_data_source: gs://ale-data-public/v1.1`
and your GCS identity. Versioned staging does not reuse arbitrary older baked
files. Evaluation downloads the requested encrypted reference before decrypting
it. Supply `ALE_REFERENCE_ARCHIVE_PASSWORD` through authorized evaluator secret
configuration, never through an agent prompt or public source.

The historical validation below retains its original snapshot and scope.

## Rollback

Old unversioned image objects and historical HF commits remain available.
Reproduce an old experiment with its original code **and** data/image pins.
Use the previous immutable revisions in the manifest history when reproducing
earlier results; current moving tags identify the October rerelease.
